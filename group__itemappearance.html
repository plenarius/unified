ItemAppearance

Readme

Lists the appearances an item can take and picks, steps through or randomizes them, with rules to leave some out.The lists are built from the icons in the module and haks, so only appearances that have an icon (and, for weapons, a model) are offered.

Usage

Call NWNX_ItemAppearance_CacheAppearances() once on module load, after the haks are available. It builds the lists and clears every rule, so add rules (NWNX_ItemAppearance_BlacklistAppearance(), NWNX_ItemAppearance_SyncAppearance()) afterwards.

Rules apply to an item class (the ItemClass column of baseitems.2da), so a rule for one base item applies to every base item sharing its class.

Ranges are written as * (any value) or a comma separated list of n, n-m, -m (up to m) and n- (n and up). A range that doesn't parse ignores the whole rule and logs a warning.

Notes

  • Simple and layered items (rings, shields, cloaks, helmets...) have a single model number and use only the first range of a blacklist rule. Weapons have three parts, each with a model and a color (0-9), written as model * 10 + color.
  • A synced weapon model can only be used on all three parts together. Stepping or randomizing a single part never lands on a synced model, since the other parts would no longer match. To reach one, use NWNX_ItemAppearance_GetNextWeaponAppearance() / GetPreviousWeaponAppearance() (step all three parts by bottom model) or GetRandomWeaponAppearance().
  • A blacklist rule for a simple or layered item may only use the first range; a rule with any other range is ignored with a warning.
  • For weapons the next and previous functions return model * 10 + color, like the random ones, not just the model.
  • The functions only return values. Apply them with NWNX_Item_SetItemAppearance() or CopyItemAndModify().

Environment Variables

There are no environment variables for this plugin.

Leave out the appearances matching every given range.

Remarks
A range is "*" (any), or a comma separated list of "n", "n-m", "-m" (up to m) and "n-" (n and up).
Simple items (rings, shields, cloaks, helmets) only use sBot, matched against the model number. A rule for one of them with any other range is ignored, with a warning in the log. Weapons match sBot, sMid and sTop against the model and sBotC, sMidC and sTopC against the color.
Parameters
nBaseItemThe BASE_ITEM_* the rule is for (it applies to every base item of the same item class).
sBotBottom model range (the model number for simple items).
sMidMiddle model range.
sTopTop model range.
sBotCBottom color range.
sMidCMiddle color range.
sTopCTop color range.

A random appearance for all three parts of a weapon.

Remarks
A synced model picked for the bottom is used for all three parts. The models are picked evenly, not the model and color together, so a model with many colors isn't favored. Only returns -1 if no weapon is allowed.
Parameters
oItemThe weapon.
Returns
The appearance; all parts are -1 if none was found.

◆ NWNX_ItemAppearance_GetNextWeaponAppearance()

struct NWNX_ItemAppearance_Weapon NWNX_ItemAppearance_GetNextWeaponAppearance ( object  oItem)

The next allowed appearance for all three parts of a weapon, by bottom model, wrapping around.

Remarks
The middle and top parts stay as they are if the rules allow it. Otherwise they take the new bottom model (all three parts do for a synced model), or failing that the first model that isn't synced. The current color is kept where the new model has it.
Parameters
oItemThe weapon.
Returns
The appearance, the current one if it is the only one allowed; all parts are -1 if none is.
